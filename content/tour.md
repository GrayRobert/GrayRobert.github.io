# Tour

All the words in the guided tour, scene by scene, in the order they appear.

Each line is `- key: text`. Edit the text after the colon. Leave the key (the part before the colon) as it is, because that is how the tour finds the line. A line whose key starts with a robot's name (`ceo-`, `cto-`, `pm-` and so on) is something that robot says in a speech bubble. The rest are captions.

Captions wait long enough to be read, so longer text simply stays on screen longer.

## overview

ROB presents these while the camera shows the whole factory.

- belief: I believe AI agents can help us build and ship good software, with people setting the direction and checking the work.
- agents: Agents make mistakes too. They overcomplicate things, take shortcuts and miss the point. They need clear guidance and good feedback.
- why-factory: So I built my CV as a dark factory: ten robots representing ten roles in software delivery, and the experience I bring to each.

## why

- start: Every idea starts at the WHY gate.
- questions: Who needs it? What value does it bring? Is it worth building? Is it safe? Is it allowed?
- rejected: We asked. No clear need, no reason to build it. Laser.
- ceo-after-laser: next.
- next: Next idea.
- unknown: Same questions. This time, we don’t know enough yet.
- to-lab: Not knowing isn’t a no. It goes to the lab.
- experiment: A small, time-boxed experiment, with security and data protection considered from the start.
- promoted: Real users found it useful. Onto the line.
- ceo-after-promoted: worth taking further.

## plan

- start: Approved ideas get a plan.
- cto-decides: build makes sense here.
- roles: The CTO works out the approach. The PM keeps the work moving.
- pm-update: priorities clear.
- steering: The roadmap goes to the steering group early, so priorities and trade-offs can be agreed before the work gets too far.

## design

- start: Then we work out how it should look, feel and behave.
- design-note: more breathing room.

## build

- start: The backend and frontend take shape. The architect checks how the pieces fit together.
- backend-update: schema migrated.
- architect-check: boundaries look right.
- sprints: We build in small steps, with regular demos: show it, get feedback, refine, repeat.

## secure

- start: Security is part of the work from the start, with checks before release.
- security-warning: that looks suspicious.
- done: Suspicious traffic blocked. Security checks complete.

## test

- start: QA checks the expected behaviour, and the things we might have missed.
- qa-finds: that’s odd.
- fixed: Reproduced. Fixed. Retested.

## ship

- start: Ready. Time to ship.

## noc

- start: Shipping is only the start of keeping it running.
- alert: 2:00am. A memory leak. Heap at 98%.
- fix: Capture a heap dump. Redeploy. Service restored. Now find the cause.
- done: I stay involved when things go wrong, restoring service and working out what needs to change.
